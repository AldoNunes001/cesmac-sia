# Checklist de revisão da primeira especificação

Marque cada item como **claro**, **ambíguo** ou **ausente**. Para todo item ambíguo ou ausente, escreva uma pergunta concreta.

## Problema e valor

- [ ] O usuário e a situação aparecem de forma específica.
- [ ] A dificuldade foi descrita sem depender de uma tecnologia escolhida.
- [ ] Evidências e suposições estão separadas.
- [ ] A alternativa atual fornece uma linha de base.
- [ ] O resultado esperado pode ser observado.

## Escopo e comportamento

- [ ] A especificação cobre uma jornada prioritária completa.
- [ ] O que fica fora do MVP está explícito.
- [ ] Entradas, saídas e precondições estão descritas.
- [ ] O fluxo principal termina em valor para o usuário.
- [ ] Ausência de informação e indisponibilidade têm comportamento definido.

## Critérios e qualidade

- [ ] Cada critério possui estado inicial, evento e resultado observável.
- [ ] Os critérios evitam adjetivos sem medida, como rápido ou inteligente.
- [ ] Pelo menos um cenário de falha está incluído.
- [ ] O risco mais grave possui um limite ou mitigação.
- [ ] Cada requisito importante pode ser ligado a um teste.

## Revisão com o PO

- [ ] As dúvidas que mudam o produto estão reunidas no final.
- [ ] Decisões confirmadas registram responsável e data.
- [ ] A versão do documento está identificada.
